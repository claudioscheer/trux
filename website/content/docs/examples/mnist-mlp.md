This is the end-to-end model example: a 784 → 128 → 64 → 10 ReLU network trained in scikit-learn, exported to a
TXM1 file, and run in Trux. It classifies all 10,000 MNIST test rows in three `gpu.launch1d` calls.

The point is not the accuracy. It is the check: the program compares its own ten last-layer values for every row with
the values numpy computed, and exits non-zero if any of the 100,000 numbers differs by more than `1e-9`.

## The problem

A port can be wrong and still look right. A transposed weight matrix, a bias added to the wrong layer, or a kernel
that reads the wrong row still produces ten numbers per row and an accuracy that looks like a model. A loss curve and
a confusion matrix do not tell you whether the kernel read the same weights in the same order.

This example compares the thing that decides the answer: the last layer. The exporter writes every row's ten values
into the file, and the Trux program has to reproduce all of them. The predicted class is then just the argmax of a
comparison that already passed.

## The model and the file

The exporter trains `MLPClassifier` on the first 60,000 MNIST rows with `random_state=0`. The run in the output below
stopped after 12 epochs with early stopping, made 237 errors on the 10,000-row test set, and reached 97.63% accuracy.
The smallest top-2 margin on that test set is 0.00434632, so no row is close to a tie.

`sample.txm` is committed: an 8/4 network with two rows, one of them a deliberate error, so `make mnist` runs without
training or a download. `model.txm` is generated by `export_mlp.py`, is about 64 MB, and is gitignored.

| Name | Shape | Dtype | Meaning |
| --- | --- | --- | --- |
| `w1` | `[128, 784]` | float | layer 1 weights |
| `b1` | `[128]` | float | layer 1 bias |
| `w2` | `[64, 128]` | float | layer 2 weights |
| `b2` | `[64]` | float | layer 2 bias |
| `w3` | `[10, 64]` | float | output weights |
| `b3` | `[10]` | float | output bias |
| `test_images` | `[N, 784]` | float | pixels, already divided by 255 |
| `test_labels` | `[N]` | int | digits 0 through 9 |
| `expected_logits` | `[N, 10]` | float | last layer from numpy, before softmax |
| `expected_predictions` | `[N]` | int | class per row from the numpy check |

Weights are stored `[out, in]`, so the kernel's inner loop walks a weight row and an input row in the same order. This
is the transpose of scikit-learn's `[in, out]` layout.

## The kernels

One generic kernel computes one element of a dense layer. Its inner loop adds the bias and then walks `k` in increasing
order. `relu` turns on the clamp for the two hidden layers; the output layer keeps the raw logits.

`main` reads the row count, the input width, both hidden widths, and the class count from the file with `gpu.dim`. That
is why the 8/4 `sample.txm` runs through the same program as the 128/64 model. Three launches fill `h1`, `h2`, and
`logits`; `gpu.to` copies the 10,000 × 10 logits back to the host, where the argmax and the comparison run.

There is no softmax kernel. Argmax of the logits is the same class as argmax of the softmax, and the raw values are
what the check compares. Softmax would only rescale them and hide absolute differences.

## Run it

From the repository root, after [building `trux`](/docs/getting-started/install/):

```bash
make mnist
```

That uses `sample.txm` when no `model.txm` exists, so it runs without training. To build the real model:

```bash
cd examples/projects/mnist_mlp
python3 export_mlp.py
```

The exporter needs `numpy` and `scikit-learn`. The first run downloads `mnist_784` from OpenML (a 15 MB compressed
file) into scikit-learn's cache. The run itself needs an NVIDIA GPU and `nvcc`, because the three layers are CUDA
kernels.

## Output

This is a real run on a GTX 1660 with CUDA 12.0. The timings vary by machine.

```text
rows 10000
errors 237
expected errors 237
predictions mismatched 0
logits compared 100000
max logit difference 1.77635683940025e-14
logits outside 1e-9 0
accuracy 0.9763
millis 95
```

| Line | Meaning |
| --- | --- |
| `errors` / `expected errors` | how many rows the program got wrong, and how many the exporter expected |
| `predictions mismatched` | rows where the program's argmax differs from numpy's; `0` is required |
| `logits compared` | `rows * classes`, the size of the last-layer comparison |
| `max logit difference` | largest absolute difference over all 100,000 values |
| `logits outside 1e-9` | values that failed the tolerance; `0` is required |
| `accuracy` | correct rows divided by all rows |
| `millis` | the three launches, the sync, and the copy back |

The program returns 1 if `predictions mismatched` or `logits outside 1e-9` is non-zero. It does not just compare the
accuracy or the error total.

## How the chain is checked

1. **scikit-learn → numpy.** After training, `export_mlp.py` runs the test set through the weights with numpy and
   compares its argmax with `clf.predict` for every row. If one row differs, it refuses to write the file.
2. **numpy → TXM1.** The same forward pass writes `expected_logits` and `expected_predictions` next to the weights and
   the test images.
3. **TXM1 → Trux.** `main.tx` mounts the file, runs the kernels, copies the logits back, and compares all 100,000
   values and all 10,000 classes.
4. **The check itself.** Changing one output weight from -0.0946 to `1e6` produced 2,327 mismatched predictions,
   2,408 logits outside the tolerance, a maximum difference of 9,983,023, and exit 1. Restoring the weight returned
   the run to 0, 1.78e-14, and 0.

## Why the last layer is not bit-identical

The largest difference is 1.78e-14, which is a few float64 ULPs on logits of order 1 to 20. numpy's matrix multiply
and the generated CUDA kernel add the 784 products in different orders, and the compiler may fuse a multiply and an
add into one FMA. Neither result is more correct; they are two roundings of the same sum.

The program uses a `1e-9` absolute tolerance. That is about five orders of magnitude above the rounding observed here,
and many orders of magnitude below a real weight or layout error. The smallest top-2 margin is 0.00434632, about
2.4e11 times the largest difference, so no classification can flip.

The two-row `sample.txm` matches exactly, not just within `1e-9`. If a different GPU, CUDA version, or BLAS ever
exceeds the tolerance, the run fails loudly instead of quietly reporting a plausible accuracy.
