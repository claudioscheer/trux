# CLI reference

```text
trux [command]

Available Commands:
  build       Compile a trux program to an executable
  completion  Generate the autocompletion script for the specified shell
  emit-c      Emit generated C or CUDA source for a trux program
  fmt         Format trux source files
  help        Help about any command
  run         Compile and run a trux program
  test        Run trux unit tests

Flags:
  -h, --help      help for trux
  -v, --version   version for trux
```

Every command accepts `-h` / `--help`. Errors are printed to stderr and make `trux` exit with status `1`.

## `trux run`

```text
trux run [--debug] <file.tx>
```

Compiles the program, builds it with the C (or CUDA) compiler in a temporary directory, runs it, and deletes the temporary
files. Standard input is forwarded to the program and its output is printed.

| Flag | Description |
| --- | --- |
| `--debug` | Write every compiler phase to `tmp/trux-debug/<name>/` and build the C code with `-O0` instead of `-O2`. |

If the program exits with a non-zero status, `trux run` prints `execute <path>: exit status N` along with the program's
stderr, and exits with status `1`.

### Debug output

`trux run --debug examples/hello.tx` prints `debug files: tmp/trux-debug/hello` before the program's output and creates
that directory (relative to the current directory) with:

| File | Contents |
| --- | --- |
| `00-source.tx` | the entry file's source |
| `01-tokens.txt` | the token stream: `line:column`, token type, lexeme |
| `02-ast.json` | the merged abstract syntax tree |
| `03-types.txt` | the function signatures and local variable types from the type checker |
| `04-ir.json` | the typed intermediate representation |
| `05-c.c` | the generated C (or CUDA) source |

The directory is cleared each time. This is the quickest way to see what each compiler stage does.

## `trux build`

```text
trux build -o <output> <file.tx>
```

Compiles the program to a native executable at `<output>`. The `-o` / `--output` flag is required.

## `trux emit-c`

```text
trux emit-c [--out-dir DIR] <file.tx>
```

Writes the generated source and the runtime headers it needs, then prints their paths. Nothing is compiled.

| Flag | Description |
| --- | --- |
| `--out-dir DIR` | Where to write the files. Defaults to `out/<name>/`, where `<name>` is the file name without `.tx`. |

The output is:

- `<name>.c` for normal programs, or `<name>.cu` if the program declares a `kernel func`
- `trux_runtime.h`, the runtime header (always)
- `trux_http_runtime.h`, if the program uses the `http` package

To compile the emitted files yourself, use the same flags `trux` uses:

```bash
cc -std=c11 -O2 out/hello/hello.c -o hello             # normal program
cc -std=c11 -O2 out/server/server.c -o server -pthread  # program using http
nvcc -x cu out/matmul/matmul.cu -o matmul               # program with kernels
```

## `trux fmt`

```text
trux fmt <file.tx>
trux fmt -r [dir]
```

Formats Trux source in place. Files that are already formatted are left untouched.

| Flag | Description |
| --- | --- |
| `-r`, `--recursive` | Format every `.tx` file under `dir` (default: the current directory), skipping `.git` and `node_modules`. |

Without `-r`, exactly one `.tx` file is required. A file that does not parse is reported and left unchanged.

## `trux test`

```text
trux test [--fail-fast] [file.test.tx | dir]
```

Finds and runs unit tests. With no argument it searches the current directory recursively for `.test.tx` files (skipping
`.git`, `node_modules`, `bin`, and `tmp`). With a file argument it runs only that file; with a directory argument it
searches that directory.

| Flag | Description |
| --- | --- |
| `--fail-fast` | Stop after the first failing test. |

See [Testing](guide/testing.md) for how to write tests.

## `trux completion`

Generated by the CLI library ([Cobra](https://github.com/spf13/cobra)): prints a shell completion script for `bash`,
`zsh`, `fish`, or `powershell`. For example:

```bash
source <(trux completion bash)
```

## Environment variables

| Variable | Effect |
| --- | --- |
| `CC` | C compiler for normal programs. Default: `cc`. |
| `NVCC` | CUDA compiler for programs with kernels. Default: `nvcc`. |

## Exit statuses

| Situation | `trux` exit status |
| --- | --- |
| Success | `0` |
| Compile error, C compiler failure, failing tests, or the program exited non-zero | `1` |
